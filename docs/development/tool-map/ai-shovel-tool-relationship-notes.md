# AI Shovel Collection：工具关系候选清单说明

本清单整理自公开目录中的工具名称/描述和现有关系数据，用于地图页面和工作流检查器的开发准备。

- 候选关系总数：94
- 替代关系候选：31
- 工作流互补候选：63
- `documented`：从目录用途及对应官方仓库定位形成的候选，需要代码实现前重新核验官方 README/文档。
- `inferred`：仅为任务逻辑层面的推断，默认不展示为事实连线。
- 所有 `displayByDefault` 均为 `false`，避免未经审核的候选关系直接铺满地图。
- 当前清单不声称工具间存在直接 API 调用或经过实测的输入输出兼容性。
- `source`/`target` 使用 GitHub `owner/repo`，但在导入前必须与最新 catalog 的 repo ID 做精确匹配；不匹配的条目不得自动导入。
- `alternative` 表示选型/功能重叠，不应作为工作流前后步骤。
- `complementary` 表示可能组成工作流，不等于直接集成；应在 UI 中标记“逻辑上可能，接口未验证”。
- 建议按 `status` / `evidenceLevel` / `inputOutputMatch` / `protocolMatch` 分层显示，禁止把未知状态当作兼容。
- 现有 `relations.json` 是生产关系数据；请将本文件作为候选输入，先审查、去重、对齐 schema，再人工审核后合并，不要直接覆盖原文件。

## 建议审核流程

1. 用当前 `catalog.csv` 校验所有 repo ID；处理大小写、重命名、失效仓库和不在目录中的仓库。
2. 打开双方官方 README/文档，确认用途重叠或工作流逻辑；把证据 URL 精确到支持该判断的页面。
3. 对互补关系检查输入输出格式、协议、认证、部署前提和是否需要人工转换。
4. 只有实际完成可复现的端到端测试后，才能标记为 `verified`。
5. `alternative` 关系可以用于工具对比，但不要在工作流检查器中当作可连接兼容关系。
